# オールスター感謝祭風 クイズシステム

複数人がリアルタイムで参加できる、
オールスター感謝祭風のクイズ回答システムです。

Socket.IO を利用したリアルタイム通信を中心に、
「状態同期」「リロード復帰」「回線差への対策」などを意識して制作しました。

# 工夫した点

## 1. リロード・再接続への対策

スマートフォン利用では、

- ブラウザリロード
- アプリ切り替え
- 一時的な通信切断

が発生しやすいと考えました。

その際、
クライアント側だけで状態を保持していると、
進行不能や表示不整合が起こる可能性があります。

そのため、
ユーザーごとに一意のIDを付与し、
進行状態をサーバー側で一元管理する構成を採用しています。

再接続時には、

- 現在の問題
- フェーズ
- 解答状態

などを再取得し、
サーバー基準で再描画することで、
途中離脱後でも同一状態へ復帰可能としています。

---

## 2. 回線差を考慮したタイム管理

早押し形式では、
0.1秒単位の差が順位に影響するため、
通信速度や端末性能によるラグが、
ゲーム性を損なう要因になると考えました。

そのため、
サーバー側から

- 問題データ
- 解答開始時間

を送信し、
クライアント側で特定時刻から受付開始する構成としています。

また、
異常なタイムや不正値を弾く処理も導入し、
公平性と体感速度のバランスを意識しました。

---

## 3. 少人数でも成立するゲームルール

本システムでは、
最大30人規模での利用を想定し、
全員参加型のルールを採用しています。

ただし、
「正解数のみ」で順位を決定すると、
プレイヤーが安全策を優先し、
早く解答するメリットが薄くなる課題がありました。

そこで、

「正解者の中で最も遅く解答したプレイヤーにはポイントを付与しない」

という独自ルールを導入しています。

これにより、

- 早さ
- 正確性

の両方を意識する必要が生まれ、
少人数でも緊張感が維持される設計を目指しました。

また、

- 「正解したが遅かった」
- 「ギリギリで最下位を回避した」
- 「早く押したのに最下位だった」

といった状態が各問題ごとに発生することで、
結果発表までの期待感を維持し、
単調になりにくいゲーム進行を意識しています。

---

# 苦労した点

Socket.IO の再接続時に、
クライアント側だけ状態が更新され、
サーバー状態と不整合が発生する問題がありました。

そのため、
クライアント側で状態を持ちすぎず、
常にサーバーを基準として再描画する構成へ調整しました。

また、
リアルタイム通信では、

- 「どのタイミングで同期するか」
- 「どこをサーバー基準にするか」

によって挙動が大きく変化するため、
実際に複数端末で検証しながら調整を行いました。
