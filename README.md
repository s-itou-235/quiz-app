# 工夫した点

## 1. リロード・再接続への対策

スマートフォン利用では、  
  
- ブラウザリロード
- アプリ切り替え
- 一時的な通信切断

が発生しやすいと考えました。  
  
その際、  
クライアント側だけで状態を保持していると、  
進行不能や表示不整合が起こる可能性があります。  
  
そのため 
ユーザーごとに一意のIDを付与し、  
進行状態をサーバー側で一元管理する構成を採用しています。  
  
再接続時には、  
  
- 現在の問題
- フェーズ
- 解答状態

などを再取得し、サーバー基準で再描画することで、  
途中離脱後でも同一状態へ復帰可能としています。  

---

## 2. 回線差を考慮したタイム管理

早押し形式では、0.1秒単位の差が順位に影響するため   
通信速度や端末性能によるラグが、ゲーム性を損なう要因になると考えました。  
  
対策として
  
出題時には  
サーバー側から「問題データ」「解答開始時間」 を送信
  
例えば、制限時間10秒の問題とした場合  
ボタンを押した時点の時刻を0秒として、そこから2～12秒を出題時間として設定し、クライアントに送信。    
クライアント側の時計で 2～12秒 を出題時間とすることで、通信ラグなどの影響を少なくしています。  
  
解答時も
クライアント側解答タイム5秒　通信速度3秒　サーバー到達タイム8秒のような解答データのとき  
  
サーバー到達タイムを有効とすると  
セキュリティ的には安全だが、端末などによるハンデが発生。  
  
クライアント側タイムを採用とする場合  
クイズの公平性としては良いが、時計をいじるなどのユーザーが不正する余地が入る。  
  
クライアント側の時計をベースに集計しつつ、不正防止などを行い  
「クライアント側のタイム」「通信速度」「サーバー到達タイム」などに矛盾や不整合がないか？　を測定  
  
異常なタイムや不正値は弾き、測定結果に応じて  
「クライアント側のタイム採用」「サーバー到達タイム採用」「通信速度をベースに補正したタイム採用」など  
公平性と体感速度のバランスを意識しました。  

---

## 3. 少人数でも成立するゲームルール

本システムでは、最大30人規模での利用を想定  
全ての問題に全員参加型のルールを採用しています。  
  
そのうえで「正解数」を中心に順位を決定すると  
プレイヤーが安全策を優先し、早く解答するメリットが薄くなる課題がありました。  
  
「間違えた人は次の問題の解答権無し」「正解者の中で最も遅く解答したプレイヤーも解答権無し」のようなルールを導入すると  

- 参加者10人で２～３問で全員脱落してしまう
- 早期に脱落したプレイヤーが退屈になる
などの問題が発生  
  
そこで  
- 全問題に全員解答権がある退屈しない強み  
- 遅く解答したときのペナルティがあるスリル的強み  

これらを掛け合わせて   
「正解者の中で最も遅く解答したプレイヤーにはポイントを付与しない」という独自ルールを導入しています。  

これにより「解答スピード」「正確性」の両方を意識する必要が生まれ    
少人数でも緊張感が維持される設計にしました。  

さらに  

- 「正解したが遅かった」
- 「ギリギリで最下位を回避した」
- 「早く押したつもりだったが最下位だった」

といった状態が各問題ごとに発生  
結果発表までの期待感を維持し、単調になりにくいゲーム進行を実現しています。

# 苦労した点

Socket.IO の再接続時に、クライアント側だけ状態が更新され、
サーバー状態と不整合が発生する問題がありました。

そのため、クライアント側で状態を持ちすぎず、
常にサーバーを基準として再描画する構成へ調整しました。

また、
リアルタイム通信では
- 「どのタイミングで同期するか」
- 「どこをサーバー基準にするか」

によって挙動が大きく変化するため、実際に複数端末で検証しながら調整を行いました。
  
  
また

回線速度が異なる端末同士でも、極端な不公平が発生しないよう
通信ラグの許容値についても検証を行いました。
どこまでを想定するか？　どの程度の状況を想定するか？　どの程度厳しくするか？  
数値調整の部分に苦労しました。  

また制限時間10秒で
クライアント側解答タイム8秒 通信ラグ3秒 サーバー到達タイム11秒 のような状況が  
サーバー側での受付締切が優先され、タイムオーバーになる現象などが発生
  
３Ｇ回線は、現代でほぼ使うことはないが  
例え４Ｇ回線でも、接続先の集中によって重くなり、３Ｇ相当の通信ラグが発生しうると考え  
  
同じタイムオーバーでも  
- クライアント側はタイムオーバー時にボタンを押せなくなる  
- サーバー側は、解答受付終了の７秒まで 集計中 として猶予  
  
このような仕様にすることで、回線差による有利不利を軽減しています。

# 既知のバグ

# 【不具合名】正解発表後の正解変更時にユーザーがリロードするとスコアが早く反映される

## 1. 概要
問題の正解発表後に、正解を変更を行った後。
ユーザーがリロードすると、正解発表前に正解変更に伴うスコア変動がそのまま反映される

## 2. 発生環境
* **OS:** Windows 11
* **ブラウザ:** Google Chrome (最新版)

## 3. 再現手順
1. 解答者側 の 画面を開く
2. 管理者側 で 問題番号0のクイズを出題する
3. 解答者側 で 制限時間内に2番を解答する。
4. 管理者側 で 正解発表までそのまま行う。（解答者側 で 正解時スコアが反映されていることを確認）
5. 管理者側 で 正解変更機能を使い。 正解を2番から1番に変更して確定。 
6. 解答者側 で リロードを行う。 

## 4. 実際の結果
* 正解発表される前に、正解変更によるスコア変動が反映される。

## 5. 期待される結果
* 正解変更によるスコア変動が正解発表後に反映

## 6. 重要度
* [ ] 重大
* [ ] 高
* [×] 中 （通常進行で、ほぼ発生しないイレギュラーな状況うえゲームの処理や公平性に影響しないため）
* [ ] 低

## 7. 補足
* 通常通りの進行でアンサーチェック中などにリロードをしても同様の現象は起きません。
　（正解発表時に 正解設定をベースにスコアデータを作成 という処理のため）

* 正解発表と同時に "その問題に関連するスコアデータ" が作成されるため
　スコアデータがある状態の場合。正解変更のデータは内部的には即時変更。
　通常は一度正解発表した際に、解答者に反映されるデータですが、
　リロードを行ったとき、現在のスコアを再反映させる処理と重なり、
　内部データの状態も反映されると思われます。
