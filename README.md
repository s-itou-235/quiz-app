# オールスター感謝祭風 クイズシステム

複数人がリアルタイムで参加できる、
オールスター感謝祭風のクイズ回答システムです。

Socket.IO を利用したリアルタイム通信を中心に、
「状態同期」「リロード復帰」「回線差への対策」などを意識して制作しました。

# 工夫した点

## 1. リロード・再接続への対策

スマートフォン利用では、  
  
- ブラウザリロード
- アプリ切り替え
- 一時的な通信切断

が発生しやすいと考えました。  
  
その際、  
クライアント側だけで状態を保持していると、  
進行不能や表示不整合が起こる可能性があります。  
  
そのため、  
ユーザーごとに一意のIDを付与し、  
進行状態をサーバー側で一元管理する構成を採用しています。  
  
再接続時には、  
  
- 現在の問題
- フェーズ
- 解答状態

などを再取得し、  
サーバー基準で再描画することで、  
途中離脱後でも同一状態へ復帰可能としています。  

---

## 2. 回線差を考慮したタイム管理

早押し形式では、0.1秒単位の差が順位に影響するため  
通信速度や端末性能によるラグが、ゲーム性を損なう要因になると考えました。

そのため、サーバー側から  
- 問題データ
- 解答開始時間

を送信  
  
出題時には    
クライアント側で特定時刻から受付開始する構成としています。    
制限時間10秒の問題とした場合  
ボタンを押した時点の時刻を0秒として、そこから2～12秒を出題時間として設定とクライアントに送信。    
クライアント側の時計で 2～12秒 を出題時間とすることで、通信ラグなどの影響を少なくしています。  
  
解答時の処理  
クライアント側解答タイム5秒　通信速度3秒　サーバー到達タイム8秒のとき  
  
サーバー到達タイムを有効とすると  
セキュリティ的には安全だが、端末などによるハンデが発生。  
クライアント側タイムを採用とする場合  
クイズの公平性としては良いが、ユーザーの不正の余地が入る  
  
クライアント側の時計をベースに集計しつつ、不正防止などを行い  
「クライアント側のタイム」「通信速度」「サーバー到達タイム」などに矛盾がないか？　を測定  

異常なタイムや不正値は弾き、公平性と体感速度のバランスを意識しました。  

---

## 3. 少人数でも成立するゲームルール

本システムでは、最大30人規模での利用を想定  
全ての問題に全員参加型のルールを採用しています。  

そのうえで「正解数」を中心に順位を決定すると  
プレイヤーが安全策を優先し、早く解答するメリットが薄くなる課題がありました。  

「間違えた人は次の問題の解答権無し」「正解者の中で最も遅く解答したプレイヤーも解答権無し」のようなルールを導入すると  

* 参加者10人で２～３問で全員脱落してしまう
* 早期に脱落したプレイヤーが退屈になる
などの問題が発生  
  
そこで  
* 全問題に全員解答権がある退屈しない強み  
* 遅く解答したときのペナルティがあるスリル的強み  

これらを掛け合わせて  
  
「正解者の中で最も遅く解答したプレイヤーにはポイントを付与しない」という独自ルールを導入しています。  

これにより  
「解答スピード」「正確性」の両方を意識する必要が生まれ  
少人数でも緊張感が維持される設計にしました。  

さらに  

- 「正解したが遅かった」
- 「ギリギリで最下位を回避した」
- 「早く押したのに最下位だった」

といった状態が各問題ごとに発生  
結果発表までの期待感を維持し、単調になりにくいゲーム進行を実現しています。

# 苦労した点

Socket.IO の再接続時に、
クライアント側だけ状態が更新され、
サーバー状態と不整合が発生する問題がありました。

そのため、
クライアント側で状態を持ちすぎず、
常にサーバーを基準として再描画する構成へ調整しました。

また、
リアルタイム通信では、

- 「どのタイミングで同期するか」
- 「どこをサーバー基準にするか」

によって挙動が大きく変化するため、
実際に複数端末で検証しながら調整を行いました。
